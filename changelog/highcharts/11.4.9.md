# Changelog for Highcharts v11.4.9 (2026-09-25)

- Security fixes. See [security advisories](https://github.com/highcharts/highcharts/security/advisories) for more details.
- Removed the bundled jsPDF and svg2pdf.js files from the `lib` folder of the npm package, and added `jspdf` and `svg2pdf.js` as optional peer dependencies.
- Updated the CSS files for [styledMode](https://api.highcharts.com/highcharts/chart.styledMode) to the versions used in Highcharts v13, and added the `css/highcharts-palette.css` file.
- Changed [breadcrumbs.style](https://api.highcharts.com/highcharts/drilldown.breadcrumbs.style) to be applied as CSS, as documented, instead of as SVG attributes.
- Fixed default URLs in the `es-modules` files, like the one for [exporting.libURL](https://api.highcharts.com/highcharts/exporting.libURL), that contained an unreplaced `@product.version@` placeholder instead of the version number.

## Upgrade notes
- The npm package no longer contains the `lib` folder. Offline PDF export still loads jsPDF and svg2pdf.js from [exporting.libURL](https://api.highcharts.com/highcharts/exporting.libURL), which points to `code.highcharts.com` by default. If `libURL` pointed to the `lib` folder of the npm package, serve these files from another location, or load jsPDF and svg2pdf.js on the page before exporting.
- If you use [styledMode](https://api.highcharts.com/highcharts/chart.styledMode) with the CSS files from the npm package, charts may look different. Dark mode now relies on the `color-scheme` CSS property and the `light-dark()` CSS function instead of `@media (prefers-color-scheme: dark)`, the dark mode colors changed, and the default font changed to the system font. To keep the previous look, use the CSS files from v11.4.8.
- The TypeScript type of `breadcrumbs.style` changed from `SVGAttributes` to `CSSObject`, which may cause type errors where SVG attributes were passed to this option.
